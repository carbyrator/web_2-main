# Ответы на вопросы к защите лабораторной работы №2

**Тема:** REST API для учёта студентов общежития.  
**Реализация:** Flask, JavaScript-клиент, хранение в JSON-файле.

## Как устроена работа

Браузер показывает HTML-страницы и отправляет HTTP-запросы через `fetch`. Flask выбирает обработчик по адресу и методу запроса. Маршрут проверяет форму HTTP-запроса и возвращает JSON вместе с HTTP-кодом. Функции валидации выполняют правила создания, изменения и удаления студентов, обращаясь к хранилищу. Данные находятся в файле `students.json` в корне проекта; файл создаётся после первого сохранения.

Основные файлы:

- `backend/app.py` — создание Flask-приложения, подключение маршрутов, выдача страниц и общая обработка ошибок.
- `backend/routes.py` — обработчики API и формирование ответов.
- `backend/validate.py` — проверка значений и фильтров, а также операции создания, изменения и удаления с проверкой правил.
- `backend/storage.py` — чтение, запись, поиск, изменение, удаление и фильтрация записей.
- `js/storage.js` — запросы браузера к API.
- `js/index.js`, `js/form.js`, `js/student.js` — поведение страниц.

Модель студента — словарь Python, который передаётся как JSON:

```json
{
  "name": "Иван Иванов",
  "group": "M3301",
  "isu": 123456,
  "dorm": 8,
  "room": "101",
  "expDate": "2027-06-01",
  "foreigner": false,
  "notes": ""
}
```

## 1. Python в серверной веб-разработке

Python на сервере принимает HTTP-запрос, выполняет логику приложения и формирует ответ. В этой работе Flask связывает URL и HTTP-метод с функцией Python. Например, запрос `GET /api/requests` попадает в `get_students`, которая получает записи и возвращает JSON. Встроенный сервер запускается командой `python backend/app.py`; он удобен для локальной разработки и демонстрации.

**Где в коде:** `backend/app.py:8` — создание приложения; `backend/app.py:54` — запуск; `backend/routes.py:36` — обработчик списка студентов.

## 2. Backend-фреймворки Python: FastAPI, Flask, Django REST Framework

Фреймворк даёт готовый механизм маршрутизации, получения запроса и формирования ответа. **Flask** небольшой и гибкий: в проекте маршруты и проверки написаны явно. **FastAPI** активно использует аннотации типов и Pydantic-модели, поддерживает асинхронные обработчики. **Django REST Framework** строится поверх Django и предоставляет средства для API, сериализаторов, авторизации и работы с моделями Django. В этой лабораторной выбран Flask; FastAPI и Django REST Framework здесь не используются.

**Где в коде:** `requirements.txt:1`, `backend/app.py:3`, `backend/routes.py:1`.

## 3. Типизация данных в Python и аннотации типов

Аннотация описывает ожидаемый тип, например `def get_student(isu: int) -> dict:`. Она помогает читать код и позволяет статическим анализаторам находить ошибки. Сама по себе аннотация обычно не запрещает передать значение другого типа во время выполнения. Поэтому данные из HTTP-запроса всё равно нужно проверять на сервере. В этой работе аннотации почти не используются: типы проверяются явно через `isinstance`, регулярные выражения и преобразование `int`.

**Где в коде:** `backend/validate.py:16`, `backend/validate.py:30`, `backend/validate.py:57`. **Важно:** не утверждать, что проект построен на аннотациях типов.

## 4. Модели данных: dataclass, Pydantic, словари и классы

**Словарь** хранит данные как пары «ключ — значение»; он прост и напрямую соответствует JSON-объекту. **Обычный класс** позволяет описать поля и методы объекта. **`dataclass`** автоматически создаёт типовые методы, например конструктор и представление объекта. **Pydantic-модель** дополнительно проверяет и преобразует входные данные по объявленной схеме. В проекте студент представлен словарём, а отдельная функция проверяет его поля. Dataclass и Pydantic здесь не применяются.

**Где в коде:** `js/form.js:49` — формирование объекта; `backend/routes.py:12` — получение JSON-объекта; `backend/validate.py:6` — проверка; `backend/storage.py:31` — сохранение словаря.

## 5. Исключения в Python и их обработка в backend-приложениях

Исключение сообщает об ошибке во время выполнения. Конструкция `try/except` позволяет обработать ожидаемую ошибку и вернуть понятный ответ вместо падения приложения. При проверке даты перехватывается `ValueError`. Ожидаемые ошибки студента функции в `backend/validate.py` возвращают как данные и код статуса; `backend/routes.py` формирует из них HTTP-ответ. Flask обрабатывает общие HTTP-ошибки и внутреннюю ошибку сервера. Неожиданная ошибка сервера даёт `500`, неверный адрес — `404`.

**Где в коде:** `backend/validate.py:49` — `try/except ValueError`; `backend/validate.py:104` — возврат ошибки проверки; `backend/routes.py:28` — перевод статуса в HTTP-ответ; `backend/app.py:20` — ошибка `500`.

## 6. Декораторы и их применение в веб-фреймворках

Декоратор — запись с `@` над функцией. Он добавляет функции поведение или регистрирует её в системе. Во Flask `@api.route(...)` связывает функцию с URL и HTTP-методом. Например, `@api.route('/api/requests', methods=['POST'])` назначает функцию обработчиком создания студента. `@app.errorhandler(...)` регистрирует обработчик исключения.

**Где в коде:** `backend/routes.py:36`, `backend/routes.py:61`, `backend/routes.py:71`, `backend/app.py:13`.

## 7. Контекст выполнения запроса и область видимости данных

Контекст запроса — данные, относящиеся к текущему HTTP-запросу: адрес, параметры, заголовки и тело. Во Flask к ним обращаются через `request`. Например, `request.args` содержит query-параметры, а `request.get_json()` получает JSON-тело. Локальные переменные функции создаются при её вызове и не служат постоянным хранилищем. Записи студентов находятся в JSON-файле; объект `request` доступен во время обработки конкретного запроса.

**Где в коде:** `backend/routes.py:12` — JSON-тело; `backend/routes.py:38` — query-параметры; `backend/storage.py:4` — путь к постоянному файлу.

## 8. Синхронный и асинхронный код в Python

Синхронная функция выполняет операции последовательно. Асинхронная функция объявляется через `async def` и может использовать `await`, чтобы ждать операцию без блокировки своего потока выполнения. Python-обработчики этой лабораторной синхронные: это обычные функции `def`. В браузерном JavaScript есть асинхронный код: `fetch` возвращает Promise, результат которого ожидается через `await`. Асинхронный JavaScript не делает Python-сервер асинхронным.

**Где в коде:** `backend/routes.py:37` — синхронный обработчик; `js/storage.js:3` и `js/index.js:32` — асинхронный JavaScript.

## 9. Итераторы, генераторы и коллекции данных

Список и словарь — коллекции Python. Цикл `for` получает их элементы через протокол итерации. Итератор выдаёт следующий элемент по запросу; генератор — удобный способ создать итератор с помощью `yield`, часто без хранения всех значений сразу. В этой работе записи хранятся списком, поиск проходит по нему циклом, а фильтрация использует списковое включение. Собственного генератора с `yield` в проекте нет.

**Где в коде:** `backend/storage.py:23` — обход списка; `backend/storage.py:50` — списковое включение при удалении; `backend/storage.py:57` — фильтрация списка.

## 10. Модули, пакеты и разделение backend-приложения по слоям

Каждый файл `.py` — модуль, который можно импортировать. Папка `backend` группирует четыре модуля. `backend/routes.py` отвечает за HTTP, `backend/validate.py` проверяет значения и выполняет операции со студентами, `backend/storage.py` читает и записывает файл. `backend/app.py` собирает приложение. Отдельного файла сервисного слоя здесь нет.

**Где в коде:** `backend/app.py:5` импортирует маршруты; `backend/routes.py:2` и `backend/routes.py:3` импортируют проверку и хранилище; `backend/validate.py:3` импортирует хранилище; `backend/storage.py:1` работает с JSON.

## 11. REST и RESTful API

REST — архитектурный подход к API: данные представлены ресурсами с адресами, а операции выражаются средствами HTTP. `RESTful` обычно называют API, которое следует этим принципам. В работе коллекция студентов доступна по `/api/requests`, отдельный студент — по `/api/requests/<isu>`. Методы `GET`, `POST`, `PATCH`, `DELETE` выполняют операции над ресурсами. Метод `QUERY` реализован дополнительно по требованию ТЗ для большого числа фильтров.

**Где в коде:** `backend/routes.py:36` — коллекция; `backend/routes.py:54` — ресурс по ИСУ; `backend/routes.py:44` — `QUERY`.

## 12. HTTP-методы и коды состояния

`GET` читает данные; `POST` создаёт запись; `PATCH` частично обновляет её; `DELETE` удаляет. Проект возвращает `200` при успешном чтении или обновлении, `201` при создании и `204` после удаления — у ответа `204` нет тела. Для ошибок используются `400` (неверное тело запроса), `404` (не найдено), `409` (занятый ИСУ), `422` (данные не прошли проверку) и `500` (внутренняя ошибка). Код сообщает клиенту результат независимо от текста ответа.

**Где в коде:** `backend/routes.py:12`, `backend/routes.py:54`, `backend/routes.py:61`, `backend/routes.py:71`, `backend/routes.py:81`; `backend/validate.py:104`; `backend/app.py:20`.

## 13. Маршрутизация, path-параметры и query-параметры

Маршрутизация сопоставляет HTTP-метод и адрес с функцией. В `/api/requests/123456` число — **path-параметр**: Flask передаёт его функции как `isu`, потому что маршрут содержит `<int:isu>`. В `/api/requests?group=M3301&dormitory=8` значения после `?` — **query-параметры**, используемые для фильтрации списка. Название `dormitory` из ТЗ переводится в поле модели `dorm`.

**Где в коде:** `backend/routes.py:54` — path-параметр; `backend/routes.py:38` — чтение query-параметров; `backend/validate.py:74` — преобразование `dormitory`; `index.html:24` — поля фильтра.

## 14. JSON, сериализация и десериализация

JSON — текстовый формат обмена данными. Сериализация превращает объект в JSON-текст, десериализация — JSON-текст в объект. Браузер использует `JSON.stringify` перед отправкой и `response.json()` при получении ответа. Flask получает JSON через `request.get_json()` и формирует ответ через `jsonify`. Для файла Python использует `json.dump` и `json.load`. Параметр `ensure_ascii=False` сохраняет русские буквы в файле читаемыми.

**Где в коде:** `js/storage.js:11`, `js/storage.js:38`; `backend/routes.py:12`, `backend/routes.py:8`; `backend/storage.py:7`, `backend/storage.py:14`.

## 15. Серверная валидация и обработка ошибок

Проверок браузера недостаточно: к API можно обратиться без интерфейса и передать любые данные. Поэтому сервер проверяет обязательные поля, формат ФИО и группы, диапазоны ИСУ и общежития, номер комнаты, дату и типы значений. Он также проверяет уникальность ИСУ. Ошибки API имеют единый вид: `{"error":{"message":"...","details":{...}}}`. `details` содержит ошибки конкретных полей, когда они есть.

**Где в коде:** `backend/validate.py:6` — проверка полей; `backend/validate.py:113` и `backend/validate.py:132` — уникальность ИСУ; `backend/routes.py:8` — формат ошибки; `backend/app.py:13` — общая обработка ошибок.

## 16. Stateless-архитектура

Stateless означает, что сервер не обязан помнить состояние предыдущего запроса, чтобы обработать следующий. Каждый запрос содержит нужный адрес, метод, фильтры или JSON-тело. Это **не означает отсутствие постоянных данных**: записи студентов хранятся в `students.json`. В браузере может временно храниться состояние открытой страницы, например выбранные фильтры, но список студентов не сохраняется там как база данных.

**Где в коде:** `js/storage.js:21` — самостоятельные запросы; `js/index.js:6` — временные фильтры страницы; `backend/storage.py:4` — постоянное хранение на сервере.

## 17. Хранение и фильтрация данных в памяти и JSON-файлах

При операции `backend/storage.py` читает JSON-файл в список Python. Поиск и фильтрация выполняются над этим списком. После добавления, изменения или удаления весь список записывается обратно в файл. Фильтр оставляет записи, для которых совпали все переданные свойства; сравнение точное, а не поиск по части слова. Браузер отправляет до трёх фильтров как query-параметры `GET`, а больше трёх — в JSON-теле `QUERY`. Число три — выбор реализации, не ограничение HTTP.

**Где в коде:** `backend/storage.py:7` — чтение; `backend/storage.py:14` — запись; `backend/storage.py:57` — точное сравнение; `js/storage.js:21` — выбор `GET` или `QUERY`; `backend/validate.py:69` — проверка фильтров.

## 18. CRUD-операции и уникальная идентификация ресурсов

CRUD — четыре базовые операции: **Create** (создать), **Read** (прочитать), **Update** (обновить), **Delete** (удалить). В API им соответствуют `POST`, `GET`, `PATCH` и `DELETE`. Отдельный студент определяется по шестизначному ИСУ в адресе `/api/requests/<isu>`. Перед созданием и сменой ИСУ приложение проверяет, что такой номер ещё не занят. Уникальность обеспечивается кодом приложения; в JSON-файле нет отдельного ограничения базы данных.

**Где в коде:** `backend/routes.py:54`, `backend/routes.py:61`, `backend/routes.py:71`, `backend/routes.py:81`; `backend/validate.py:30`, `backend/validate.py:113`, `backend/validate.py:132`.

## Что важно не перепутать

- Серверный код здесь **синхронный**. `async/await` используется в JavaScript-клиенте.
- Модель студента — **словарь**, а не dataclass или Pydantic-модель.
- Stateless не означает отсутствие хранения: данные записываются в `students.json`.
- Фильтрация выполняется по **точному совпадению** значений.
- JSON-файл подходит для учебной работы, но при множестве одновременных записей понадобятся блокировки или база данных.
